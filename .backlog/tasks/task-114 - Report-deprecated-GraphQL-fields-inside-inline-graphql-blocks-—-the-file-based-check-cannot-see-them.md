## The gap

`DeprecatedGraphQLField` (TASK-112) is `SourceCodeType.GraphQL`, and that type is reached only from the `.graphql` file extension (`SOURCE_CODE_TYPE_BY_KEY` in `platformos-common/src/app/types.ts`). An inline `{% graphql %}` body travels inside a `.liquid` file, so no GraphQL-typed check sees it.

`GraphQLInlineCheck` (TASK-113) does read those bodies, but runs only graphql-js's default rule set. `NoDeprecatedCustomRule` is deliberately absent from `specifiedRules`, so deprecation is reported for a query in a `.graphql` file and not for the same query written inline.

## Measured exposure

Eight application trees, linted with `configs/recommended.yml` against the published platformOS SDL. On `POS/marketplace-dcra` alone the new check reports **214** findings that nothing reported before, beside 414 from the file-based check.

Inline bodies use deprecated members at more than twice the rate of `.graphql` documents — measured over the same corpus by running graphql-js's deprecation rule directly: 61% of readable inline bodies against 29% of `.graphql` documents.

## What was built

`DeprecatedGraphQLFieldInline`, a LiquidHtml check at `Severity.WARNING`, recommended.

A separate check rather than a branch of `GraphQLInlineCheck`, because severity is a property of the check: an invalid query fails when executed and an inline deprecation runs fine. Merging them would make every deprecation an error, or every invalid inline query a warning.

Two helpers were extracted so the four checks cannot drift apart:

- `inlineGraphQLDocument` (`checks/utils.ts`) — the guard/slice/parse/docset sequence both inline checks need, including the four documented reasons it gives up (not a graphql tag; body is not all text so it interpolates Liquid; body does not parse, which is left alone because graphql-js and the platform's parser disagree in measured ways; no docset).
- `deprecationProblems` (`utils/graphql-deprecations.ts`) — runs `NoDeprecatedCustomRule` and positions each finding at the deprecated NAME rather than the node, because a Field's own range spans its alias and its whole sub-selection.

## Also fixed here: the two checks from TASK-112 and TASK-113 were disabled

`packages/platformos-check-node/configs/{all,recommended}.yml` are generated by `yarn generate-factory-configs` and are tracked in git. Neither was regenerated when those checks were added, so both files listed 54 checks against a registry of 56, and a check absent from the config does not run. Both were off for every consumer — the CLI, the language server and the supervisor — which is why a corpus sweep for `DeprecatedGraphQLField` returned zero. Regenerating is now part of this task's acceptance criteria so the next check cannot ship the same way.
